Rules for the pr-reviewer runs on this repository's pull requests, read from the base branch.

- CI is switched off. `.github/workflows/ci.yml` is disabled on GitHub, so no gate has run before you. Run the four checks its steps name (`cargo fmt --check`, `cargo clippy`, `cargo test`, `script tests`) with the flags it gives them. The two test suites take about a minute on the reviewer host. Do not run a release build.
- The reviewer host reaches no Windows machine, and nothing else checks Windows. Skip `docs/skills/use-windows/SKILL.md`, and when the diff touches platform code, list Windows under Not verified.
- For each `.specs/<module>/<module>.yml` the diff touches, read the clauses the PR claims to implement and check the code against them clause by clause. Their `checks` entries are tests `cargo test` runs.
- Run `docs/skills/inspect/scripts/run-scenario.sh --list` and only the scenarios that cover the touched behavior. Read the artifacts, not only the exit code. Add no scenarios. If none covers the behavior, probe it another way and say so.
- egui seams worth probing: same-frame ordering (a draft committed in the same frame as a control click), focus loss, repaint requests, input routing precedence (modifier clicks, pan gestures, double-click hit tests), and history recording around multi-step edits (undo after paste, duplicate, transfer). The app tests in `src/app/tests/` show how to drive the harness. A probe test appended there, run, and deleted is the fastest reproduction.
- Never run `scripts/update-smoke-macos.sh`, `scripts/update-smoke-windows.sh`, or the `semantic-search-real-install` scenario. Never write into `library/` or `models/`.
